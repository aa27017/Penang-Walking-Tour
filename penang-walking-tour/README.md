# ジョージタウン歴史散策（Penang George Town Walking Tour PWA）

ペナン島ジョージタウン（UNESCO世界遺産地区）の歴史スポットを、日本語の解説を読みながら徒歩で回るためのWebアプリです。iPhoneのSafariで「ホーム画面に追加」すると、ふつうのアプリのように全画面で使えます。ビルド作業は不要で、静的ファイルをそのまま GitHub Pages に置くだけで動きます。

## できること

| 機能 | 内容 |
|---|---|
| 地図 | Leaflet + OpenStreetMap。全スポットのピン（番号付き）と、推奨ルートの線（実際の道に沿った徒歩ルート） |
| ツアー | コースA／B／C を推奨順に表示。「次へ」で進むと訪問済みとして記録（localStorage） |
| スポット詳細 | 解説（300〜500字）、歴史的背景、見どころ、所要時間、入場料、営業時間、写真撮影ポイント、注意事項、出典 |
| 現在地 | 次のスポットまでの距離と方角（矢印をタップするとコンパス表示に切り替え） |
| 近接通知 | スポットの約50m以内に近づくとバナーを表示（設定でON/OFF） |
| 音声読み上げ | 日本語で読み上げ（Web Speech API）。こどもモードではゆっくり読みます |
| 用語集 | ショップハウス、コンシ、プラナカン、海峡植民地など20語 |
| 実用情報 | 暑さ対策、宗教施設のマナー、トイレ・休憩、Grabの使い方、緊急連絡先 |
| オフライン | アプリ本体・解説・写真は自動でキャッシュ。地図は「地図を保存」ボタンで事前に取得 |
| こどもモード | 画面上部の「おとな／こども」切り替え。こども向けの文章（ふりがな付き）、「みつけてみよう！」クイズ、スタンプラリーと認定証、壁画さがし、休けいカード |

### コース

- **A：ヘリテージ王道コース**（約3.5〜4時間＋休憩、歩行約5km）：聖母被昇天大聖堂 → 州立博物館 → セントジョージ教会 → シティホール → エスプラネード → コーンウォリス要塞 → 時計塔 → プラナカン・マンション → リトルインディア → 観音寺 → マハマリアマン寺院 → カピタン・クリン・モスク → 孫文ゆかりの地 → ヤップ・コンシ → アチェ通りモスク → クー・コンシ → ストリートアート → クラン・ジェッティ。最初の E&Oホテル／ブルー・マンションは「寄り道」扱いです。
- **B：短縮コース**（約1.5〜2時間、歩行約1.8km）：観音寺 → マハマリアマン寺院 → カピタン・クリン・モスク → 孫文ゆかりの地 → クー・コンシ → ストリートアート → クラン・ジェッティ
- **C：郊外スポット**（Grabで移動）：極楽寺、ペナンヒル

順番は、OpenStreetMapで確かめた座標をもとに2-opt法で歩行距離が最短になるよう調べたうえで、OSMの道路データで徒歩ルートを引いています。

## パソコンで動かしてみる

Service Worker と位置情報は `http://localhost` か `https://` でしか動かないため、ファイルをダブルクリックで開くのではなく、簡易サーバーを使います。Macなら最初からある Python で動きます。

```bash
cd ~/Documents/penang-walking-tour
```

```bash
python3 -m http.server 8000
```

ブラウザで http://localhost:8000 を開きます。止めるときは Ctrl+C です。

## GitHub Pages で公開する手順

1. GitHub にログインし、右上の「＋」→「New repository」を選びます。
2. Repository name に `penang-walking-tour` などと入力し、**Public** を選んで「Create repository」を押します（無料プランの GitHub Pages は公開リポジトリが必要です）。
3. このフォルダをアップロードします。いちばん簡単なのはブラウザを使う方法です。
   - 作成したリポジトリのページで「uploading an existing file」をクリック
   - Finder で `penang-walking-tour` フォルダの**中身すべて**（`index.html` や `data` フォルダなど）を選んでドラッグ＆ドロップ
   - 「Commit changes」を押す
   - ※ `.nojekyll` は隠しファイルなので、Finder で ⌘+Shift+. を押すと表示されます。なくても動きますが、入れておくと安心です。

   ターミナルを使う場合は次のとおりです（`<ユーザー名>` は自分のものに置き換えます）。

   ```bash
   cd ~/Documents/penang-walking-tour && git init && git add . && git commit -m "first commit"
   ```

   ```bash
   git branch -M main && git remote add origin https://github.com/<ユーザー名>/penang-walking-tour.git && git push -u origin main
   ```

4. リポジトリの「Settings」→ 左メニュー「Pages」を開きます。
5. 「Build and deployment」の Source で **Deploy from a branch** を選び、Branch を **main**、フォルダを **/(root)** にして「Save」を押します。
6. 1〜2分待つと、ページ上部に `https://<ユーザー名>.github.io/penang-walking-tour/` というURLが表示されます。これがアプリのアドレスです。

> URLを知っている人は誰でも見られます。個人情報は入れないでください（このアプリは入力した内容をすべて端末の中にだけ保存し、サーバーには送りません）。

## iPhone でホーム画面に追加する手順

1. iPhone の **Safari** で、上の GitHub Pages のURLを開きます（Chrome などではなく Safari を使ってください）。
2. 画面下の **共有ボタン**（四角から上向き矢印が出ているアイコン）をタップします。
3. メニューを上にスクロールして **「ホーム画面に追加」** をタップします（見つからない場合は、いちばん下の「アクションを編集」から追加できます）。
4. 名前（「GT散策」）を確認して、右上の **「追加」** をタップします。
5. ホーム画面にできたアイコンから起動すると、Safariのアドレスバーがない全画面表示になります。

### 出発前にやっておくこと（Wi-Fiのある場所で）

1. ホーム画面のアイコンから一度アプリを起動し、全部の画面を一度ずつ開きます（写真・解説がキャッシュされます）。
2. 「情報・設定」タブ →「地図を保存」を押し、「保存済み：172枚」になるまで待ちます。
3. 地図タブの ◎ ボタンを押して、位置情報の利用を「許可」します。
4. 必要なら「近づいたら知らせる」をONにします。
5. 機内モードにして、アプリが開けること・地図が表示されることを確かめておくと安心です。

### iPhone での注意

- **位置情報**：許可しなかった場合は、iPhoneの「設定」→「プライバシーとセキュリティ」→「位置情報サービス」→「Safariのサイト」で「使用中のみ」にします。
- **コンパス**：次のスポットまでの矢印をタップすると、「動きと方向」へのアクセス許可を求められます。許可すると矢印が進む方向を指します。許可しない場合、矢印は「北を上」にした方角を示します。
- **近接通知**：アプリを開いている間だけ動きます（画面を消したりほかのアプリに切り替えたりすると止まります）。
- **音声読み上げ**：消音モード（マナーモード）だと音が出ないことがあります。日本語の音声は iPhone の「設定」→「アクセシビリティ」→「読み上げコンテンツ」→「声」で追加・変更できます。
- **データの保存**：訪問記録やスタンプは端末の中（localStorage）に保存されます。iOSは、ホーム画面に追加したアプリを長い間使わないとデータを消すことがあります。旅行の直前にもう一度開いておきましょう。

## スポットを編集・追加する（data/spots.json）

`data/spots.json` は、テキストエディタ（Mac の「テキストエディット」をプレーンテキストモードにするか、VS Code など）で編集できます。保存したら GitHub にアップロードし直すと反映されます（データはネットワーク優先で読み込むため、次回起動時に新しい内容になります）。

### スポット1件の項目

| 項目 | 説明 |
|---|---|
| `id` | 半角英数字の一意な名前（例 `"khoo"`） |
| `category` | `colonial` / `religion` / `chinese` / `other` / `suburb` |
| `name` | `{ "ja": 日本語名, "en": 英語名, "local": 現地表記 }` |
| `lat`, `lng` | 緯度・経度（OpenStreetMapで右クリック→「この場所を表示」で調べられます） |
| `summary` | 一行説明 |
| `description` | 解説（300〜500字が目安） |
| `background` | 歴史的背景 |
| `highlights` / `photo_spots` / `cautions` | 見どころ／撮影ポイント／注意事項（文字列の配列） |
| `duration_min` | 所要時間の目安（分） |
| `fee` / `hours` | `{ "text": 表示する内容, "ref": 補足（任意）, "verified": true/false }`。`verified:false` の場合は画面に「要確認」と表示されます |
| `sources` | 出典 `[{ "title": ..., "url": ... }]` |
| `verified` | 座標と内容を確認済みかどうか |
| `photo` | `{ "src": "images/spots/xxx.jpg", "credit": 作者, "license": "CC BY-SA 4.0", "license_url": ..., "source_url": ... }`。写真がない場合は `null`（プレースホルダーが表示されます） |
| `kids_text` | こども用の文章（100〜150字）。ふりがなは `<ruby>漢字<rt>かんじ</rt></ruby>` と書きます |
| `kids_quiz` | `{ "question": 問題, "answer": 答え }`（どちらもルビ可） |
| `murals` | （ストリートアートのみ）壁画さがしリスト |
| `transport` | （郊外のみ）移動の目安 |

### コースへの追加

`courses` の中の `stops` に `{ "id": "スポットのid", "stay_min": 滞在分 }` を追加します。`"optional": true` を付けると「寄り道」扱い、`"note"` で補足を表示できます。`rests` はこどもモードで表示する「休けいしよう」カードです（`after` に指定したスポットのあとに表示）。

> ルートの線（`route.line`）は自動では更新されません。順番を大きく変えた場合は線と実際の順番がずれるので、`route` を削除すると線を表示しなくなります。

### アプリ本体（HTML/CSS/JS）を変更したとき

`sw.js` の先頭にある `VERSION` の値を上げてください（例 `'v1.0.1'`）。上げないと、iPhoneに古いファイルが残ることがあります。

## オフライン地図について

「地図を保存」で取得するのは、旧市街（ズーム14〜17）と極楽寺・ペナンヒル下駅の周辺（ズーム14〜17）の合計172枚です。OpenStreetMap のタイルサーバーは、ズーム13以上で250枚を超える一括ダウンロードを利用規約で禁止しているため、範囲をツアーに必要な部分に絞っています（範囲は `js/app.js` の `TILE_AREAS` で変更できますが、250枚以内に収めてください）。保存範囲の外は、オフラインのときは灰色になります。

## 動作確認の結果

- macOS 上のローカルサーバー＋Chromium系ブラウザ（スマホ幅 375×812 に設定）で確認しました。地図とピン・ルート、ツアーの進行、訪問記録、詳細画面と写真、こどもモード（ふりがな・クイズ・スタンプ・認定証・壁画チェック・休けいカード）、近接バナー（擬似的な位置情報を使用）、読み上げの開始・停止、地図タイル172枚の保存、サーバー停止後のオフライン起動まで動きました。
- **Lighthouse は実行できていません。** この作業環境に Node.js と Chrome がなかったためです。なお、Lighthouse 12（2024年）以降は「PWA」カテゴリ自体が廃止されています。代わりに、インストールに必要な条件を個別に確かめ、すべて満たしていました：HTTPSまたはlocalhost、manifest（name・short_name・start_url・scope・`display: standalone`）、192px／512px／maskableアイコンの実寸、apple-touch-icon（180px）、fetchハンドラ付きService Workerが有効、start_url がオフラインで返ること、viewport・theme-color・lang の指定。
  Chrome の DevTools →「Lighthouse」タブ、または「Application」→「Manifest」でも確認できます。
- 実機（iPhone Safari）での確認はまだです。とくに位置情報・コンパス・読み上げの音声は、出発前に実機で試してください。
